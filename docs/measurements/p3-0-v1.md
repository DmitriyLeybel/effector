## Method

- Corpus revision: `p3-0-synthetic-v2`
- Schema revision: `trajectory-measure/v2`
- Tokenizer: `tiktoken-rs` `0.12.0`, encoding `o200k_base`, mode `ordinary`
- Executable command: `cargo run --locked --manifest-path tools/trajectory-measure/Cargo.toml -- check`
- Tokenizer operation: `tiktoken_rs::o200k_base()?.count_ordinary(rendered)`
- Canonical renderer: `TOOLS`, `ASSISTANT_TOOL_CALL`, `TOOL_RESULT_TEXT`, and `TOOL_RESULT_STRUCTURED`; recursively sorted compact JSON and preserved array order. This is not named-client evidence.
- Generated JSON-RPC envelopes are canonical. Protocol-v3 envelopes use normalized synthetic parameters for unimplemented branches and deterministic image base64; they are reproducible planning evidence, not shipped branch ABIs. Model rendering excludes image base64 and reports artifact bytes separately once.
- Every fixture has unit weight. Each of the six workflow classes has the same fixture count.
- Class-table token metrics are body-only. The eligible final context contains all-five discovery once followed by every eligible fixture in checked-in source order.
- Aggregate per-turn tokens replay each eligible fixture with all-five discovery and its fixed prompt in every visible prefix.
- Ordinary session totals are independently rendered and tokenized. Candidate break-even searches 100 exact complete-workload repetitions.
